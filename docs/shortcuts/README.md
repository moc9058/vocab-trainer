# 読み解くショートカットの設定

更新: 2026-10-30。アプリのApp Intentsと、iPhoneの「ショートカット」アプリを接続する手順です。コントロールセンターには2つの「ショートカット」コントロールを追加し、それぞれを割り当てます。アプリ更新だけでは、作成済みのショートカットやコントロールの設定は変わりません。

この資料は手動で再現できる構成です。未検証の`.shortcut`ファイルやiCloud配布リンクは用意していません。OSによるアクション名の違い、撮影タイミング、選択範囲の受信は本人の端末で確認してください。2026-10-30にiOS 26.6.2の本人のiPhoneで既存ショートカットを修正しました。実機の撮影・解析結果と未確認事項は[iOS検証記録](../ios-verification.md)を参照してください。

## 1. 画像を読み解く

名前を「画像を読み解く」にし、次の順序にします。

| 順序 | アクション | 設定 |
| --- | --- | --- |
| 1 | コントロールセンターを表示 | 青い動作パラメーターを **非表示** に変更する。「Siriを終了して続ける」で代用しない |
| 2 | 待機 | 1秒。閉じるアニメーションの後に撮影する。対象画面に戻ったことを実機で確認し、必要なら調整する |
| 3 | スクリーンショットを撮る | 撮影結果のマジック変数を後段へ渡す |
| 4 | Vocab Trainer → 画像を読み解く（Read an image） | 「画像（Image）」に手順3の出力を設定。「画像の入力元（Image source）」は「スクリーンショットのショートカット（Screenshot shortcut）」 |

「コントロールセンターを表示」は、[Appleの更新案内](https://support.apple.com/en-jo/121131)にある表示・非表示の両方に対応するiPhone/iPad用アクションです。検索で「コントロールセンター」を入力し、追加後に動作を変更します。Macでは実行できません。画像欄の「選択」を長押しすると、撮影結果の「スクリーンショット」を変数として指定できます。通常のタップではファイル選択になるため注意してください。

「アプリを開く」「ファイルを選択」「写真を選択」「最新の写真を取得」はこの手順に入れません。撮影に失敗した場合は停止し、別の画像を黙って使わないでください。端末の写真ライブラリへの保存も不要です。

コントロールセンターの「＋」→「コントロールを追加」→「ショートカット」から、このショートカットを割り当てます。小红书・财新で表示中の画面を取得し、Vocab Trainerのプレビューがその画面であることを確認します。OCR後は画像内の文章をタップして選択し、「選択した部分を解析」を押します。共有画像・画像選択も同じ確認方式です。辞書への登録は解析後に項目ごとに行います。

コントロールセンターや実行バナーが写る場合は、閉じる操作と待機を調整します。安定しなければ、同じ「撮影→Intent」の手順を背面タップ／アクションボタンに割り当ててください。物理ボタンで撮った画像を共有シートのショートカットへ渡す方法や、アプリの「別の入力方法」→「画像を選ぶ」もあります。代替入口の成功をControl Center撮影の成功とは扱いません。

## 2. 選択した文章を読み解く

名前を「選択した文章を読み解く」にし、「共有シートに表示」と、利用できる場合は「画面上の内容を受け取る」を有効にします。入力はテキスト・リッチテキスト・URLを対象にします。入力なし時の自動Clipboard取得は設定しません。

```text
共有入力／画面上の入力
  → 入力がある？
      はい → 複数項目なら使う項目を選択
           → テキスト／リッチテキスト：文字列に変換
                → Vocab Trainer「選択した文章を読み解く」
                   文章 = 入力文字列、文章の入力元 = 共有された文章
           → URLのみ：Vocab Trainer「読み解く文章を入力」
                出典URL = HTTPSリンク（任意）
      いいえ → メニューから選択
           「コピーした文章を使う」→ クリップボードを取得
                → 空でない場合のみ「選択した文章を読み解く」
                   文章 = 取得した文字列、文章の入力元 = コピーした文章
           「入力方法を開く」→ Vocab Trainer「読み解く文章を入力」
           「キャンセル」→ ショートカットを停止
```

URLを文字列として受信Intentに渡しても、アプリはリンクだけと判定して本文の入力を案内します。HTTPS・資格情報なしのリンクは出典候補として保持します。本文＋URLの共有は確認画面で編集できます。「URLの内容を取得」「記事を取得」などのアクションは加えません。

文章を選択しただけでControl Centerを開いても、アプリによっては選択範囲が渡されません。その場合は選択→「コピー」→Control Center、または選択→「共有」→このショートカットを使ってください。古いClipboardを今回の選択範囲だと判断しないよう、Vocab Trainerで原文を確認してから解析します。本文を自動取得できたことにはしません。

Control Centerにもう一つ「ショートカット」コントロールを追加し、この文章用ショートカットを割り当てます。独自のControl WidgetやShare Extensionは不要です。[Appleの画面入力仕様](https://support.apple.com/en-euro/guide/shortcuts/apd350ce757a/ios)は対応アプリからの入力に限られます。

## 3. 設定の診断と更新

| 症状 | 確認点 |
| --- | --- |
| 画像・ファイルの選択画面が出る | Imageが「毎回尋ねる」になっていないか確認し、撮影アクションの出力変数へ変更 |
| Vocab Trainer自身が撮影される | 撮影より前にアプリを開いていないか確認 |
| Control Centerが写る | 閉じる操作・待機を再確認。安定しなければ背面タップ等へ |
| 文章の入力を毎回尋ねられる | Textへ共有入力／Clipboard取得結果を接続 |
| 前にコピーした文章が出る | 選択だけで起動していないか確認し、明示的にコピーして再実行 |
| リンクだけが届く | 本文の選択共有／コピーか画像取得へ切り替える |
| アクションが見つからない | `ios:sync`後にXcodeでiPhoneを更新し、一度アプリを開く。Shortcutsの古いアクションを差し替える |
| 受信通知から開けない | 回答同期・登録・編集・保存の完了を待つ。作業中の画面を自動で置き換えない |
| 下書きを保存できない／受信箱がいっぱい | 受信画面で不要な入力を破棄して再試行 |

古い「画像を読み解く」「選択した文章を読み解く」アクションは引き続き利用できます。追加した入力元指定の既定は共有画像／共有文章です。必須Image/Textを使わず案内だけを開く場合は、新しい「読み解く文章を入力（Open reading input）」を使います。
